# mi6bridge — звук звонка через raw ALSA

[English](README.md) · **Русский**

Маленький статический бинарник на Go (arm64, без зависимостей), который гоняет
звук звонка между приложением шлюза и голосовым DSP телефона напрямую через
ALSA, в обход `AudioRecord` / `AudioTrack`. Нужен на Xiaomi Mi 6 (MSM8998) и
запускается от root.

## Зачем

На этой прошивке штатный путь Android до голосового DSP не доходит:

| Что пробует приложение | Что получается |
|---|---|
| `AudioRecord` с `VOICE_DOWNLINK` | политика ведёт в `afe-proxy-record` — тишина |
| `AudioRecord` с `VOICE_CALL` | открывается, но uplink и downlink смешаны |
| `AudioTrack` для подачи звука в звонок | в audio policy нет `incall_music_uplink`, звук играет в динамик, а не собеседнику |

Сами нужные пути в ядре есть, просто Android их не открывает. Поэтому
помощник открывает PCM-устройства сам:

- **GSM → SIP:** захват `/dev/snd/pcmC0D27c` (MultiMedia9). Маршрут
  `MultiMedia9 Mixer VOC_REC_DL` даёт только то, что пришло из сети, — голос
  GSM-абонента, без микрофона телефона.
- **SIP → GSM:** воспроизведение в `/dev/snd/pcmC0D1p` (MultiMedia2). Маршрут
  `Incall_Music Audio Mixer MultiMedia2` подмешивает звук в голосовой uplink
  внутри DSP — собеседник слышит SIP-сторону.

Оба направления цифровые: ни динамик, ни микрофон в тракт не входят.

## Как работает

```
приложение ──stdin  (S16_LE mono, 8 кГц)──► очередь ≤200 мс ──► PCM 1  (Incall_Music → uplink)
приложение ◄─stdout (S16_LE mono, 8 кГц)─── FIR 48→8 кГц ◄───── PCM 27 (VOC_REC_DL ← downlink)
                                   stderr ──► лог (OPEN / STATS / STOP)
```

- **Захват на 48 кГц и понижение своим FIR-фильтром** (Blackman, срез ~3,6 кГц
  при 8 кГц на выходе). Если просить у DSP сразу 8 кГц, он передискретизирует
  сам, и широкополосная речь VoLTE получается с шипением на свистящих.
- **Очередь воспроизведения ≤ 200 мс.** Пачка пакетов из сети не превращается в
  постоянную задержку: лишнее отбрасывается (`dropped`).
- **Ритм задаёт PCM, а не сеть.** Если очередь пуста, в uplink идёт тишина
  (`starved`), DSP не останавливается.
- Работает, пока открыт stdin и жив stdout; останавливается по SIGTERM.
- Маршруты микшера помощник **не трогает** — их выставляет приложение до
  запуска (`setupCmd` профиля `msm8998()`) и снимает после (`restoreCmd`):
  `Voc VSID`, `VOC_REC_DL`, `Incall_Music`, глушение микрофона `DEC7/DEC8`.

## Кто запускает

- Magisk-модуль кладёт бинарник в модуль, `service.sh` при загрузке копирует его
  в `/data/local/tmp/mi6bridge` (root:root, 755).
- Приложение (`rtp/AlsaBridge.kt`) на каждом звонке выставляет маршруты и
  запускает через root:
  ```
  exec /data/local/tmp/mi6bridge -in 27 -out 1 -rate 8000 -dtmf
  ```
  Его stderr попадает в logcat с префиксом `helper:`.
- После звонка приложение закрывает stdin, добивает процесс (`pkill -x
  mi6bridge`) и возвращает маршруты.

## Параметры

| Флаг | По умолчанию | Что это |
|---|---|---|
| `-card` | `0` | ALSA-карта |
| `-in` | `27` | PCM захвата (MultiMedia9) |
| `-out` | `1` | PCM воспроизведения (MultiMedia2) |
| `-rate` | `8000` | частота на stdin/stdout: 8000 или 16000 |
| `-cap-rate` | `48000` | частота захвата, кратна `-rate` |
| `-period-ms` | `20` | длина периода |
| `-max-queue-ms` | `200` | сколько звука SIP-стороны держать впереди воспроизведения |
| `-dtmf` | выкл | сообщать о кнопках абонента GSM (см. ниже) |

На другом телефоне номера PCM почти наверняка другие — смотреть
`cat /proc/asound/pcm` и проверять маршруты на живом звонке.

## Кнопки абонента GSM

В VoLTE нажатия приходят пакетами telephone-event (RFC 4733), и их съедает
IMS модема: в звуке тона нет, в телефонию Android ничего не приходит. При этом
модем сообщает о каждом нажатии индикацией `QMI_VOICE_DTMF_IND` (события
`IP_INCOMING_DTMF_START` / `STOP`) всем клиентам QMI VOICE, которые подписаны
на DTMF. На этой прошивке ей никто не пользуется.

С `-dtmf` помощник подписывается сам через IPC router (`AF_MSM_IPC`, сервис
QMI VOICE 9) и пишет в лог:

```
DTMF ready (voice 0:0x3d)
DTMF start 5
DTMF stop 5
```

Приложение превращает эти строки в пакеты RFC 4733 на SIP-плече, с payload
type из SDP сервера. Пока кнопка нажата, эти пакеты идут вместо звука.

Голосовой сервис пускает только группы `radio` (1001) и `net_raw` (3004)
(`/vendor/etc/sec_config`), поэтому помощник добавляет их себе. Если
подписаться не вышло, в логе будет `DTMF off: …`, а звук работает как обычно.

## Лог

Раз в 10 с строка вида:

```
STATS captured=80000 played=80800 starved=247 queue=800 dropped=15200 xrun_in=0 xrun_out=0 peakRMS=8566
```

| Поле | Что значит |
|---|---|
| `captured` / `played` | сэмплов отдано в stdout / сыграно в uplink (≈ 8000 в секунду) |
| `starved` | периодов, когда очередь была пуста и играла тишина (звук из сети не успел) |
| `dropped` | сэмплов отброшено из-за переполнения очереди (пачка пакетов из сети) |
| `xrun_in` / `xrun_out` | переполнения / опустошения буферов ALSA |
| `peakRMS` | пиковая громкость захвата за интервал: ~0 — тишина, тысячи — речь |

## Сборка

```sh
cd tools/mi6bridge
go test ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags='-s -w' -o ../../magisk/mi6bridge .
```

`build.sh` делает то же самое, если установлен Go. Тесты проверяют децимацию: 1 кГц проходит без потерь, 6 кГц (выше половины
частоты на выходе) подавляется.
